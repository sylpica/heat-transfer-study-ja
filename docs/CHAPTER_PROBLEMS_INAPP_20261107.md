## 統合方式（導線と表示）

導線は2か所。

1. **目次（リーダーのサイドバー）**：各章の節一覧の下に
   「章末問題・参考文献（日本語訳を収録）」のボタンを常設した
   （`data-chapter-extras`）。押すとその章の最終節へ移動し、章末パネルを
   開いた状態にする。あわせて、第1〜5章の目次に従来表示されていた
   backMatter の「章末問題」「参考文献」行（「翻訳下書き・未移行」の
   プレースホルダ表示）は、この実導線に置き換えた（該当2 id のみ除外し、
   他の backMatter 行があれば従来どおり表示する）。book.json の台帳
   自体は変更していない。
2. **読書記事の末尾パネル**：表示中の節が属する章について、
   「第N章 章末問題・参考文献」の見出しと開閉ボタンを記事末尾
   （自分のメモ・しおりの後、「この画面について」の注記の前）に置いた。
   どの節を読んでいても、その章の章末へ進める。

表示は常時全展開にしない3段構え。

- パネル（初期は閉）→ 開くと章データを取得し、件数つきの2グループ
  「問題（N問）」「参考文献（N件）」をそれぞれ `<details>` で開閉。
- 問題は1問ごとに `<details>`（初期は閉）。サマリーに問題番号と
  本文冒頭72字のリード文を示し、開くと既存の `renderBookBlock` で
  本体（本文・小問・与えられた式・図の代替説明・ヒント・一部解答・
  原本表記の確認事項・出典ページ）を描く。
- 問題に付随するデータ表（第6章 問題6.47/6.48/6.49、第10章 10.48/10.52、
  第11章 11.31 の `table` ブロック）は、直前の問題のグループに含めて
  その問題の中で描く（ブロックの出現順で機械的に帰属させる）。
- 参考文献はグループ内に一覧表示する。第1章のみ、参考文献の前置き
  （歴史的文献と発展的テキストの文献案内、`preambleBlocks`）を
  グループ冒頭に描く。
- 描画は節本文と同じ経路（`renderBookBlock` ＋ `linkedReaderText`）を
  再利用するため、数式・図・表・ヒント等の既存ブロック表現がそのまま
  使え、用語リンクも既存機構で効く。パネル末尾に、出典ページ・
  専門家校閲未実施・原図未収録の注記を置いた（説明文は下部側の原則）。
- パネルの文字サイズ・行間は本文と同じく読書設定
  （`--reader-scale` / `--reader-line-height`）に従う。

## 読み込み設計

- **章単位の遅延読み込み**：初期表示では章末データを一切取得しない
  （検証で確認：パネルを開くまで `data/chapter-problems/` への
  リクエストは発生しない）。パネルを初めて開いた章についてだけ
  `./data/chapter-problems/chapter-NN.json`（35〜94 KB／章、
  全11章で約612 KB）を取得し、メモリ内キャッシュに保持する。
  同じ章の開閉では再取得しない。
- 取得したデータは表示前に検証する：エンベロープ（`chapterId`・
  `language='ja'`）、見出し・件数の整合（`problems.count` は problem
  ブロック数、`references.count` は reference ブロック数と一致）、
  全ブロックが既存の `validBookBlocks` を通過すること。不合格または
  取得失敗の場合は部分表示せず、失敗の明示と「もう一度読み込む」
  ボタンを出す。
- **ビルドゲートの意味は不変**：節ファイルちょうど76件の検査は
  節ファイル数の検査のまま。章末データは `content-manifest.json`
  （節ファイル専用の一覧）には入れず、アプリ起動時の一括読み込み
  対象にもしていない。
- **公開ビルド**：`scripts/build-public-site.mjs` が
  `data/chapter-problems/` のファイルを検証して dist へコピーする。
  ファイル名パターンに合うものがちょうど11件でない場合、または
  エンベロープ・件数が合わない場合はビルドを失敗させる。11ファイルは
  キャッシュ版数（`publicCacheName`）の計算対象にも含めた。
- **オフライン／PWA**：11ファイルを `sw.js` の `APP_SHELL` に追加し、
  初回インストール時にプリキャッシュする（あわせて実行時キャッシュも
  従来どおり働く）。データ量は合計約612 KB で、初回表示の重さには
  影響しない（アプリシェル側の追加のみ）。

  対象外。
