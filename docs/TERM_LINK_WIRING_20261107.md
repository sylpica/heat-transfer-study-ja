## 高速マッチャー（性能対策）

用語集ページ（504 行）と検索スニペットは一括描画のため、従来の
`renderTermLinks`（呼び出しごとに候補 1,420 件を再コンパイル）では
全用語の全フィールドで約 13.1 秒かかる。`term-links.mjs` に
`compileTermMatcher` / `renderTermLinksFast` を追加:

- 候補を先頭文字（小文字化）でバケット化し、テキストを左から走査。
  最も早い位置の有効な一致が勝ち、同位置では候補順（最長ラベル優先）。
  ラテン文字境界ルールと falseCompounds ルールは従来と同一。
- 大文字小文字折り畳みで長さが変わるテキストは従来の compiledMatches に
  フォールバック（従来の安定/不安定の分岐と同じ扱い）。
- 等価性: 出荷コーパス 29,060 テキスト（問題・用語集・全76節・発展講義・
  独自ノート）で従来描画とバイト単位で差分 0 件（limit 6）。excludeId
  （自己除外）モードでも差分 0 件。
- 速度: 全 504 語 × 全フィールド（brief/meaning/beginner/detail/example）
  = 26 ms（従来方式 13,096 ms）。

## 2文字ラベルの判断（実測）

コーパス 28,606 テキスト（問題全フィールド、用語集全フィールド、全76節の
全文字列、独自ノート、発展講義、ガイド、app.js）で出現と文脈を実測した。

- 蒸発（evaporation）: 261 件。すべて蒸発そのものか派生語（蒸発潜熱・蒸発部・
  蒸発器・蒸発冷却）。蒸発散は 0 件。→ 許可リストに追加。
- 液滴（droplet）: 103 件。すべて液滴の文脈（液滴飛散・液滴分布・液滴同伴・
  滴状凝縮）。→ 追加。
- 管群（tube-bank）: 38 件。すべて管群の文脈。別名「管束」も 22 件すべて管束の
  文脈（管束相関式など）。→ 両方追加。
- 濡れ（wetting）: 205 件。ただし「濡れ縁」（濡れ縁長さ＝水力直径の周辺長、
  約40件超。他の用語の説明文内にも出現）と「濡れた断面・濡れた閉流路」
  （約15件）は濡れ性（§9.7/§9.10）とは別概念群で、「濡れ割合」（22件）は
  乾き度の文脈の濡れ fraction。用語集の「濡れ」項目へ自動リンクすると
  系統的に誤誘導になる。→ 追加しない（現状維持）。用語集の閲覧・検索・
  ディープリンクからは到達可能。

根拠の一般原則: 複合語の先頭一致は、意味が分岐しない場合に限り許容されて
きた（黒体放射など）。分岐する複合語は falseCompounds で遮断する既存方針と
同じ判断。

## 配線した経路

（検証結果は別節）

1. 式ブロック説明文: `renderBookBlock` の formula で `highlight()` →
   `linkedReaderText(…, 4)`。数式そのものは従来どおりリンクしない
   （A2-UXS-10 の意図的仕様を維持）。
2. 図キャプション: caption を `<strong>` 内で `linkedReaderText(…, 3)`、
   description を `linkedReaderText(…, 4)`（従来は caption 無リンク、
   description はハイライトのみ）。
3. 表の要素: caption(3)・見出し(2)・セル(3)・注記(4) を linkedReaderText 化。
4. 書籍ブロック内リスト: 見出し(3)・項目(4)。問題ブロック: 小問(4)・続き(5)・
   ヒント(4)・一部解答(4)・sourceNote(4)。
5. 参考文献: 注記（note）のみリンク化。著者・題名・出版情報は書誌データ
   として従来どおりプレーン（用語リンクの対象は説明文という線引き）。
6. 用語集自身: 行の brief(3)・意味(4)・初学者説明(4)・詳細(4)・例文(3) を
   高速マッチャーでリンク化（自己リンクは excludeId で除外）。単位・式の行は
   シートと同様プレーン。用語シート: brief・初学者説明・詳細・例文を
   `renderTermLinks` でリンク化（自分自身は除外）。シート内の用語から
   さらに別用語のシートへ遷移できる。
7. シミュレーター:
   - 入力欄ラベル・ヘルプ: `linkTermTextNodes` に `{labels:true}` オプションを
     追加し、render() の後処理で `.sim-fields` を処理。ラベル内テキストは
     リンク化するが、入力欄クラスタ（`.input-unit`：input・単位・select）は
     常に除外。ラベル内リンクのクリックは委譲ハンドラの preventDefault で
     ラベルの既定動作（入力へのフォーカス移動）より先にシートを開く
     （回答選択肢ラベルで実績のある同じ仕組み）。入力欄は outputs-only
     再描画で差し替わらないため、タイピング中の攪乱はない。
   - 式カード: 式そのもの（`<strong>`）は数式として従来どおり無リンク。
     カード内の説明文（3レンダラ共通の向き説明）を linkedQuizText(…, 3)。
   - 結果見出し: 拡張モードの head.label / head.sub、基本モードの結果説明文、
     非定常モードの結果説明文と適用性カード本文を linkedQuizText 化。
   - グラフ見出し・注記: 3レンダラの chart-heading（title / note）を
     linkedQuizText 化。
8. 横断検索スニペット: `renderTermLinksFast`（limit 3、検索ハイライト併用）。
   結果タイトルは `<button>` 内のため従来どおりハイライトのみ（ボタン内に
   role=button を入れ子にしない）。
9. ガイド: セクション見出し（h2）を linkedQuizText(…, 3)、要約を
   linkedQuizText(…, 4)。目次リンク内のタイトルは従来どおりプレーン。

対象外として据え置いたもの:
- レッスン図・シミュ図の figcaption は出典注記の定型文であり内容キャプション
  ではないため対象外。
- 発展講義の出典リストは `<a>` 内のため従来どおり（リンク内リンクを作らない）。

### ブラウザー配布スイートのテスト適応

`tests/browser-distribution.mjs` の問題バンク検証ループ（444問）が、
パネルの hidden 判定（count() のスナップショット）が画面遷移の描画と
競合し、トグルを開かずに hidden パネル内の項目をクリックして
タイムアウトする事象で停止した。配線前の取り込みコミット（b42997e）
でも同一箇所・同一症状で再現する既存のテスト側レースであり、配線は
無関係。検証意図を変えない範囲で次の適応を行った:

1. パネルの存在を待ってから hidden を判定し、hidden の場合はトグルを
   クリックして「開いた」ことを waitForFunction で確認してから項目を
   クリックする（開く→開始するという意図と全アサーションは不変）。
2. ループの進捗ログを 50 問ごとに 1 行追加（ログのみ）。
3. ページの既定タイムアウトを 180 秒へ延長。751 項目・約 10 万 px の
   バンクパネルを開くレイアウトは、この VM では新規プロファイルでも
   実測 25〜50 秒かかり、既定の 30 秒を超える。パネルが開いた状態で
   クイズ開始画面を再描画するクリック全般が同様に遅いため、個別の
   クリックではなく既定値を延ばした。状態（学習記録）の肥大は無関係
   であることも実測で確認した。待ち時間を延ばすだけで、検証内容は
   変えていない。

完走結果: Chromium で最後まで完走し合格（全 444 問のバンク検証を含む
全セクションを通過し、最終サマリ行まで出力、エラー・タイムアウト
なし）。この VM では他ラインのスイートと競合し、所要は約 1 時間だった。
なお、適応なしの初回実行と、適応 1 のみの実行では上記のレース／
タイムアウトで停止したため、適応 1〜3 の全てが完走に必要だった。
