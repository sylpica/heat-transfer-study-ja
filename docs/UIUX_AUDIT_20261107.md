## 発見と修正

### F0（先行課題分）簡易シミュレーター: モード選択ボタン群の圧迫 — #9・#1 → 修正済み
- 問題: 20モードのタブボタンが常時展開し、375px で占有高さ 883px、
  シミュレーター本体の開始位置は y=1,207px だった。
- 修正: 現在モード名＋「モードを変更」ボタンのバーに縮小し、展開時のみ
  カテゴリ別（伝導 / フィン・熱交換器 / 非定常 / 対流 / 放射 / 沸騰・拡散）の
  タブリストを表示。WAI-ARIA タブの矢印キー操作は維持し、Escape で閉じる動作を追加。
- 実測: バー高さ 61px（375/390/1280/1920 全幅）。本体開始位置 y=370px（F1 適用後）。

### F1 全画面: ページ見出しの二重表示 — #6 → 修正済み
- 問題: `pageHeading(eyebrow, title)` の呼び出し 17 件中 15 件で eyebrow と title に
  同じ文字列が渡され、全画面で同じラベルが見出しの上下に二重表示されていた
  （例: 「学習ホーム／学習ホーム」）。
- 修正: `pageHeading` 内で eyebrow === title のとき eyebrow を描画しない。
  異なる組（例: 簡易シミュレーター／時間とともに変わる物体温度、問題演習／N / M 問）は従来どおり表示。
- 実測: `.page-heading` 高さ 114px → 98px（375px）。全画面・全幅で
  先頭カード位置が 16px 上がった（モバイル 305→289px、PC 208→192px 等）。

### F2 シェルヘッダー: アプリ名下の薄いサブタイトル — #5 → 修正済み
- 問題: トップバーのブランド表示が「熱移動を学ぶ」の下に小さなサブタイトル
  「読む・解く・ふり返る」を常時表示していた（キャッチフレーズ風サブタイトルに該当）。
- 修正: サブタイトルを削除し、aria-label も「熱移動を学ぶ ホームへ」に簡素化。
- 実測: トップバー高さは 76px で不変（固定高さのため）。表示要素のみ削減。

### F3 問題画面: 問題バンク 751 問の常時展開 — #9・#1 → 修正済み
- 問題: 演習設定フォームの下に、収録 751 問全件のボタンリストが常時展開し、
  カード高さ 100,994px、画面の文書高さは 102,502px（375px）に達していた。
- 修正: カード見出しに「問題一覧を開く／閉じる」トグル（aria-expanded /
  aria-controls、操作後にフォーカスがトグルへ戻る）を追加し、既定で閉じた。
  リスト自体は DOM に残し（751 件）、クリックでその問題から演習を始める既存挙動は不変。
- 実測: 閉じた状態のカード高さ 93px。文書高さ 102,502 → 1,585px（375px）、
  46,280 → 958px（1280px）。開閉・問題開始（見出し「1 / 1 問」）を実ブラウザで確認。

### F4 設定画面: 節ごとの対応表 76 行の常時展開 — #9・#1 → 修正済み
- 問題: 「翻訳と確認の状況」カード内の節ごと対応リスト（76 行）が常時展開し、
  `.content-progress` 高さ 3,883px、設定画面の文書高さ 6,626px（375px）の一因だった。
- 修正: 要約（収録節数と進捗バー）は常時表示のまま、対応表だけを
  「節ごとの対応表を開く／閉じる」トグル配下に移した（F3 と同じ方式）。
- 実測: 文書高さ 6,626 → 2,916px（375px）、5,133 → 1,716px（1280px）。
  76 行は DOM に残り、開閉を実ブラウザで確認。

## 要判断（ユーザー判断を受けて修正）

- J1 用語集: 修正済み（2026-11-07、ユーザー判断「両方直す」）。
  475 語全件を全文カードで常時描画しており、文書高さ 335,711px（375px）だった。
  修正方式: 用語をコンパクトな行表示（用語名＋1 行要約＋「詳しく見る／閉じる」
  ボタン）にし、全文（定義・式・例・出典・リンク・関連問題）は DOM に保持した
  まま hidden で制御してその場で展開する。ディープリンク到達時（用語シートの
  「用語集で詳しく見る」、横断検索の用語結果）は対象語を展開状態で描画し、
  従来どおり scrollIntoView で該当行へ移動する。展開状態は画面遷移後も保持
  される。検索・絞り込みは不変。選定理由: `#term-<id>` の DOM 存在という
  リンク仕様を壊さずに初期表示だけを軽くでき、新規機構を持ち込まずに済む。
  実測: 文書高さ 375px で 335,711 → 82,570px（−75.4%）、1280px で
  158,694 → 36,081px（−77.3%）、390px ダークで 80,116px。横はみ出し 0・
  pageerror 0。ジャンプ確認: 通常シミュレーターの使い方ガイドの用語リンク
  （26 件・17 語ユニーク）から代表 4 語（fin、isotherm、thermal-conductivity、
  biot-number）と横断検索経由の biot-number で、対象行が展開済みで表示され
  見出しがビューポート内へ入ることを実ブラウザで確認。用語集内検索
  （「熱伝導率」→ 27 行、先頭は thermal-conductivity）、クリア後の 475 行
  復帰、行トグルの開閉往復も確認。ページ全体の scroll-behavior: smooth
  （従来仕様）のため、遠方への到達には最大で約 0.8 秒のアニメーションを要する。
- J2 簡易シミュレーター: 修正済み（2026-11-07、同判断）。
  F0 後も出力カード（グラフ）の開始位置は y=1,662px で、入力カード自体が
  1 列レイアウトで 1,274px あるためだった。
  修正方式: (1) 「式」と「前提」の 2 カードを 1 つの折りたたみ（ネイティブ
  details「式と前提を確認する」、既定は閉）へ集約した。チェック項目 #3
  （普遍的な説明・参考情報は後ろへ）に基づく。出力専用再描画でも開閉状態が
  保持される。(2) 600px 以下では入力フィールドを横並び行（ラベル列 1fr ＋
  入力列 148–160px、補足説明は全幅で下段）化し 1 項目の高さを圧縮した。
  項目・順序・計算・結果表示・キーボード操作は不変。セレクトを含む
  フィールドだけは縦積みを維持した（自動選択肢など選択肢ラベルが長く、
  横並びでは文字切れの恐れがあるため。チェック項目 #2 を優先）。選定理由:
  入力の意味的な並びと操作順序を一切変えず、参考情報の格納と行高の圧縮
  だけで出力到達を早められるため。
  実測（375px、出力カード開始 y）: conduction 1,662 → 1,254（−408）、
  resistance 1,965 → 1,439（−526）、radiation 1,619 → 1,196（−423）、
  transient 2,236 → 1,696（−540）、fin 1,920 → 1,424（−496）、
  exchanger 2,209 → 1,694（−515）、slab 2,220 → 1,680（−540）。
  入力カード高さは conduction で 1,274 → 867px。折りたたみ（閉時）は 66px。
  全測定モードでフィールドの縦方向の切れ 0・横はみ出し 0・pageerror 0。
- J3 dynamic 側の画面: この系統（68d2875）には dynamic/ が存在しない
  （ファイル数 0 を確認）。動的実験室の各ページの UI/UX 監査は、統合時に
  シミュレーション側ブランチの系統で実施する。本記録の対象はシェル側の
  通常シミュレーター入口画面まで。
