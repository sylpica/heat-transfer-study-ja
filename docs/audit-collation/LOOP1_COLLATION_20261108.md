## 4. 判断不一致の決着（多数決によらず、根拠を明記）

### 4.1 用語アンカー（C1-01 の P1 対 R1-P2-03 の P2）→ P1

Muse 側の P2 は「ガイド内用語リンク」という単一経路の再現に基づく。Codex の指摘を受けて照合担当がコード実物で全着地経路を確認したところ、欠陥の範囲はより広かった。用語シートの「詳細」遷移と検索結果の用語遷移は、保存済みの単語帳モード（cards）が有効な状態では対象行が DOM に存在せず、着地しても用語が表示されない（S0 の当該ハンドラはモードをリストへ戻さない）。すなわち S0 では「用語への直接移動」という設計された機能が、ガイド経路では100%、アプリ内経路でも利用者が単語帳を使っている通常状態で機能しない。これは R1-P1-01（正規の利用経路で教材全体が読めなくなる＝P1）と同種の「機能の全面不全」であり、文言の誤り（R1-P2-02＝P2）とは性質が異なる。用語集自体は通常ナビゲーションで到達できるため P0 にはしない。以上により **P1** と決着する。

### 4.2 公開デプロイ（C1-04 の P1 対 R1-P3-18／R1-P3-20 の P3）→ P2

Codex の2つの指摘部分（旧ブランチへの checkout 固定、npm ci の欠落）は Muse も別々に実測していた（R1-P3-20、R1-P3-18）。相違は重大度だけである。P1 としない根拠：これは利用者の利用経路の欠陥ではなく、現行の公開サイトは意図した現行版（2026-11-05 配信）を配信中で、ワークフローを今実行しても旧内容が再公開されるだけで新たな誤配信にはならない。P3 としない根拠：この手動ワークフローが公開の唯一の経路であり、(a) 統合版を公開しようとしても旧ブランチが選ばれて黙って旧内容が出る、(b) 参照先を正しても依存導入がなくクリーンなランナーではビルドが失敗する、という2点が重なり、公開経路そのものが機能していない。手続き上の軽微事項を超えるため **P2** と決着する。なお Codex の修正（承認済み40桁SHAを必須入力化し、そのSHAを checkout、npm ci を追加）は、誤認による旧内容公開を構造的に防ぐもので、Muse 側が「1行追加」としていた案より完全であるため採用した。

### 4.3 読書時間テスト（C1-07 の P2 対 R1-P3-07 の P3）→ P3、対策は Codex 案を採用

製品の記録動作が正しいことは両側が独立に裏付けている（Muse のプローブ実測 8.365秒／8.578秒と帰属の仕組み、L3 ラインの構造的説明、Codex の実測）。欠陥はテスト側の測定方法にのみあり、失敗の方向は「正しい製品を不合格にする」偽陰性型で、合格すり抜け（C1-05）とは証拠への害が異なる。また当該テストはどの CI ワークフローからも実行されない。以上により **P3** と決着する。対策については、Muse 側が「基準を弱めないため変更しない」としていたのに対し、Codex の修正は10秒／90秒のアサーション数値を一切変えず、起動前に時計を固定して実時間の位相ずれだけを除去するものである（diff で不変を確認）。これは基準の緩和ではなく測定方法の是正であり、Muse 側が次ラウンド以降の判断材料として求めていた「計測方法の見直し」に当たるため採用した。統合ツリーで当該スイートを実行し、読書時間の確認項目を含む全19項目が合格した（§6）。

### 4.4 用語着地の実装（2つの実装の競合）→ Codex 実装を採用

同じ欠陥に対する修正が両側に存在したため、検証可能な範囲の広い方を選んだ。Muse 実装（`ffa6e17`）はハッシュ着地（起動時・hashchange）を直し、単語帳モードの保存時もリストへ戻すが、用語シート詳細と検索結果の遷移は S0 の旧コードのままで、cards 保存時には対象行が存在しない問題が残る。Codex 実装は起動時・hashchange・詳細・検索の4経路を `openGlossaryTerm` に統一し、対象行の展開・スクロールに加えてフォーカス移動を行い、単語帳の並び順と位置は保持する。統合にあたって Muse 実装側の `focusTermFromHash` は撤去し、Codex 実装へ一本化した。未知IDの着地は両実装とも用語集一覧への穏当な着地になる（Codex 実装では route 判定で用語集へ落ちる）。採用後の検証は §6 のとおり（Muse の probe-term-hash と Codex のブラウザー回帰テストの双方が合格）。

### 4.5 用語集注記の文面（2つの文面）→ Muse 文面を採用

両文面とも虚偽（「翻訳本文は未収録」）を除去し、独自作成であること、翻訳が読書画面に収録されていること、専門家校閲が未実施であることを含み、事実内容は等価である。Muse 文面はアプリ内の他の画面と同一の「読書画面」表記で統一され、Muse 側の回帰アサーション（`tests/app.test.mjs`）が固定している文面でもあるため、こちらを採用した。Codex 文面（「読む」表記）は採用しなかったが、内容上の誤りではない。Codex の回帰テストの注記アサーション（未収録でないこと・校閲未実施の表示）は Muse 文面でも満たすことを統合ツリーで確認した。あわせて Codex の `32d6957`（配信テストの要約文を「日本語訳76節」に訂正、アサーション不変）は受理した。

### 4.6 問題集カバレッジの分類（P2 欠陥 対 残件記述）→ P2 を維持

事実（独立検算 376/751問、残りは自己確認＋構造検証＋標本照合の水準、いずれの照合でも誤答は未発見）は両者一致する。指令書第9章の基準では検証不足は P2 とされており、Muse の登録はこの基準に基づく。Codex はこれを格下げしたのではなく自らの台帳に登録しなかっただけであり、明示的な反論はない。よって R1-P2-01 を未解決の P2 として維持し、収束条件（第4.1節）に対するブロッカーとして扱う。
