## 5. 候補として棄却したもの（測定方法の誤りを訂正した記録）

- 「式(8.13b) の形が想定と異なる」（W1 初回）：照合文字列に原データ表記 `^(…)` を使ったため、描画側で `<sup>` 化されたテキストと一致しなかった。W1b で描画 HTML の構造を直接確認し、修正形であることを確定した。製品の欠陥ではない。
- 「例題8.3 に (RaL/Pr)・新訳注・NūL がない」（W1 初回）：ロケータが本文の例題段落ではなく発展教材の段落を先に拾っていた。W1b で `δ/L = 3.936` を含む本文段落に特定し直し、全項目の表示を確認した。製品の欠陥ではない。
- 「対象問題と異なる問題が表示された」「解説の積分定義が見つからない」（W3): `textContent` では添字が `h_x` のような下線つき表記にならず `hx` と平たく読めるため、照合文字列が一致しなかった。開始ボタンの ID・選択肢・解説の内容で対象問題と解説（平均の積分定義）を確認済み。製品の欠陥ではない。
- 「リロード後にブックマークが保持されない」（W4 初回）：リロード直後の描画途中に行内ボタンを読んだため null になった。W4b で再測定し、localStorage `heat-study-ja:v1` にブックマークが残存すること、検索後の行で ★ が表示されることを確認した。製品の欠陥ではない。

## 7. A5-L3-F01 の修正と再確認（追記・修正実施）

- 原因（実測で特定）：`.question-meta` は `flex-wrap` のないフレックス行で、両アイテムとも `min-width: auto` のため最小コンテンツ幅以下に縮めない。左アイテムの最小幅は `white-space: nowrap` の校閲状態ピル「算術・モデル前提の内部確認済み／外部専門家校閲前」（10px フォントで 256px)、右の `.question-actions` の最小幅は ☆ボタン 44px + gap 6px + 「問題を報告」ボタンの最小幅 28px = 78px。合計 256 + 10 + 78 = 344px（`.question-meta` の scrollWidth 実測と一致）が、375px でのカード内容幅 301px（390px でも 316px）を超過する。このため actions がカード右端の外へ押し出され（実測：カード右端 359px に対し actions 右端 381px)、報告ボタンは最小幅 28px に潰れてラベルが1文字ずつ縦に折り返していた。構造側ではなく CSS の折り返し欠如が原因。
- 修正：`styles.css` の `.question-meta` に `flex-wrap: wrap` を追加（1プロパティのみ）。収まる幅では従来どおり1行の space-between 配置のままで、狭幅では actions が次の行へ回り込む（`.reader-toolbar` 等の既存パターンと同じ折り返し方）。
- 回帰テスト：`tests/browser-distribution.mjs` の問題カード表示フロー（F01 の再現問題 `supp-applied-1-1-v1` を開く既存箇所）に、390px・375px の両幅で「文書はみ出しなし／actions がカード内／報告ボタンの高さ ≤45px（1行）」の3点アサートを追加した。ルート単位の幅チェックは問題タブ初期画面しか見ておらず、カード表示中の状態が欠けていたための追加。同スイート自体の本ツリーでの完走は §6 の申し送りどおり公開・配信段階で実施する（本修正では未実施）。
- 検証（修正後の公開ビルドに対し Chromium 実測、証拠画像 `usage-evidence-loop3/w3-q01-after-{375,375-answered,390,1280}.png`）：

  - 390px（同2問）：文書はみ出し 0、actions はカード内、報告ボタン 76×44px・1行。

  - pageerror・コンソールエラー（既知の local-content-manifest.json 404 を除く）なし。
- 全 Node スイート：1798件 = 1793 pass / 0 fail / 5 skip。公開ビルド成功（dist の `.question-meta` に `flex-wrap: wrap` が含まれることを確認）。
