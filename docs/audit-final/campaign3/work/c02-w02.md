## 疑いが解消した項目（候補化せず）

1. **表示の圧縮（ステップ5ほか）**: 原典 PDF 73 ステップ5第1行は「T_w = −0 + 0 + C₂」と書くが、アプリ blocks[18] は「T_w = C₂」に圧縮する。同様に例題2.2ステップ5（PDF 75）の「T₁ = 0 + C₂」はアプリで「T₁ = C₂」に圧縮される。いずれも数学的に等価で結果（C₁、C₂）も一致するため、誤りとして候補化しない。
2. **中間段の省略（q_wall 検算・例題2.2ステップ8）**: 原典 PDF 74 の q_wall 表示は中間段 k[q̇/k·x − q̇L/(2k)]_{x=0} を含むが、アプリ blocks[26] は初項と最終結果 −q̇L/2 のみを示し、中間の導出は explanation（∂T/∂x = −(q̇/k)x + q̇L/(2k)）で補われている。原典 PDF 76 ステップ8も同様に −k·d/dx(T₁ − (T₁ − T₂)/L·x) の中間段をアプリ blocks[44] は省略するが、追加される中間値 k(T₁ − T₂)/L は正しい。最終結果が原典と一致し数学的に偽でないため候補化しない。
3. **評価記法（F30重点確認）**: 本範囲内の評価記法は PDF 74 の q_wall における |_{x=0} のみで、アプリ blocks[26] は初項に |_{x=0} を保持している。なお重点指定の F30 本体（例題2.5・式（2.23））は本範囲外（`data/sections/2-3-ja.json`、原典 PDF 81–82）だが、保持確認のため現行データを直接読んだ: 境界条件ブロック（0-based index 45）は左辺が括弧直後の添字形 h̄(T − T∞)_{r=rₒ}（縦バーなし）・右辺が −k(∂T/∂r)|_{r=rₒ}（縦バーあり）であり、式（2.23）ブロック（0-based index 47）は両辺とも角括弧＋添字形 [ … ]_{r=rₒ}（縦バーなし）である。第2次修正（CF2-048 / C02-F30）の形がそのまま保持されており、一様化への逆行はない。
4. **中心線記号 ℄**: 図2.6（PDF 74）の中心線記号とピーク注記の T_℄ は、アプリ alt でも ℄ のまま保持されている。平文への置換はない。
5. **通常の数学イタリック x**: PDF 73・75 の T(x = 0) 等の x は通常の数式イタリック字形であり、独立したスクリプト体記号とは判断しなかった。字形候補として記録しない（テキストレイヤでは判定していない）。
6. **平均バー・Q のドット（恒常裁定の確認）**: 本範囲の原典に平均バー付きの h は現れない（対流係数が登場しない範囲）。Q̇ へのドット付加は恒常裁定により不所見とし、再登録しない。原典にないバーの追加も本範囲では検出せず。
7. **書籍側の表記**: PDF 76 の式（2.16）直後段落は原典自体が「記号 R_{t_slab} を与える。R_t の次元は…」と添字の有無を併用しており、アプリ blocks[47] も同じ併用を再現している。書籍側の表記として分離し、アプリの誤りとして候補化しない。
