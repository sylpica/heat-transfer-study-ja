# 円柱横流れ過渡モデルの開発画面（2026-11-07、Muse 本線）

検証済みモデル核 `dynamic/dev/cylinder-crossflow-transient.mjs`（開発文書
`docs/dynamic/CYLINDER_CROSSFLOW_TRANSIENT_DEVELOPMENT.md`）に対する開発画面を
新設した。核と風速→h モジュール `dynamic/dev/wind-heat-transfer.mjs` には
一切変更を加えていない。画面は開発専用（公開ビルドの allowlist 外、
releaseApproved=false のまま）。

## 追加ファイル

- `dynamic/dev/cylinder-crossflow-transient.html` — 画面本体
- `dynamic/dev/cylinder-crossflow-transient-ui.mjs` — 入力収集・時間操作・表示
- `dynamic/dev/cylinder-crossflow-transient-view.mjs` — 断面模式図と半径方向分布グラフ
- `tests/dynamic-cylinder-crossflow-transient-browser.mjs` — 実ブラウザー検証

様式は既存の開発画面（環状フィン・風速→h）に倣い、共通CSS `cavity.css` を使う。
計算はメインスレッドで実行し、履歴（最大1200コマ）をメモリーに保持して
「1コマ戻す／時刻0へ戻す」で核の restore により状態を復元する。

## 画面の構成

- 条件：検証済みプリセット（内部勾配ケース／集中定数ケース／例題7.8）、
  直径・長さ・固体物性（k・ρ・cp）・初期温度・流体温度・半径方向セル数。
- h の与え方：直接指定と風速からの推定（教科書§7.6）の排他切替。
  風速側は流体物性（膜温度で評価）と膜温度の表面温度（空欄＝初期温度）を入力する。
- 時間操作：1コマの物理時間、再生／一時停止／1コマ進める／1コマ戻す／時刻0へ戻す。
- 表示：断面模式図（セル平均温度の同心環表示、測定セルの輪）、半径方向の
  温度分布グラフ、測定位置スライダー、代表温度（測定セル・中心セル・
  表面温度＝半セル抵抗で再構成・体積平均）、h とその出所。
- 診断（折りたたみ）：Bi、集中定数時定数 τ、表面積・体積、表面熱流束・
  表面熱流（内向き正）、積算熱量、内部エネルギーと収支誤差、safeDt、
  風速推定時は Re_D・Pr・Pe_D・Nu_D・膜温度と使用相関、警告文。
- 前提（h は周方向平均・表面一様・時間一定、流体は一様で温度一定、端面・
  放射・局所分布は解かない）は冒頭の注意書きと末尾の「理論・仮定・適用限界」
  に明示した。一般的説明は画面下部に置く常設チェックリストに従った。

## 検証（実測、Chromium／Playwright）

`tests/dynamic-cylinder-crossflow-transient-browser.mjs` が合格：

1. **画面値と核の一致**：内部勾配ケース（直接h=500、セル32）を2 s進め、
   測定セル・中心セル・表面温度・体積平均温度の画面表示が、同一条件の核の
   値と表示桁（小数4桁）まで一致。同じ画面値は独立 Python 参照
   （CYLINDER_CROSSFLOW_REFERENCE_20261107.json の t=2 s サンプル）とも
   0.05 K 以内で照合（セル32の離散化誤差の範囲）。
2. **例題7.8プリセット**：画面の h = 2833.981736 W/(m² K) が50桁検証値
   2833.9817356038657 と表示精度内で一致し、使用相関は式(7.66)、
   Re_D = 457、Nu_D も核と一致。0.005 s 進めた後の平均・表面温度も核と一致。
3. **集中定数プリセット**：画面の τ = 342.65 s。t=τ まで進めた平均温度の
   減衰比は 0.367994 で e⁻¹ との差は 1.2×10⁻⁴（核側テストの予算内）、
   画面の平均温度は核と表示桁まで一致。
4. **復元**：1コマ戻すと初期フレームへ正確に戻る（表面温度は半セル抵抗の
   再構成値で、核の初期スナップショットと一致。一様温度 400 K より低い）。
5. **拒否の verbatim 表示**：Bi>10（h=20000）では核の理由
   「Bi=hR/k=… が本モデルの開発範囲上限 10 を超えます」をそのまま表示し、
   受理済みの表示と時刻は不変。風速側の範囲外（Re_D>10⁷）では風速→h
   モジュールの理由がそのまま伝播。h=0 では「熱伝達率hは正の値で
   指定してください。」を表示。
6. **レイアウト**：幅 375／390／1280／1920 × ライト／ダークで横はみ出し
   なし、読み出しテキストの切れなし、pageerror 0、localStorage 不変。
   スクリーンショットを work/ に保存（390ダーク・375ライト）。
   WebKit は未実施（この環境では起動不可のため）。

## 不変の確認

- 全 Node スイート：従来値 1,605件＝1,600合格／0失敗／5スキップを維持
  （本画面の追加はブラウザーテストのみで、Node スイートの件数は不変）。
- 公開ビルド成功。dist は日本語76節ちょうど・dist/dynamic 47エントリ・
  dist/dynamic/dev は存在せず、本画面のファイルは公開経路に含まれない。

## 残る制限

- 風速推定の流体物性は利用者供給値のみ（物性データベースは持たない）。
- 実機・支援技術・オフライン・公開URLでの動作は未確認。
- 画面から熱流束分布（radialFlux）そのものの表示は行っていない
  （表面熱流束・熱流はスナップショットの診断量で表示）。
