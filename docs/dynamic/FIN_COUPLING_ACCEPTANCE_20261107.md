## (a) 周囲流体温度の時間変化

### 条件1：正規の入力経路の新設 — 充足

- `distributedConvection.temperatureSchedule` を新設した（形式：`[{at, temperature}, ...]`、区間一定。`at` 以後の周囲温度はそのエントリの値、それ以前は基準 `temperature`）。
- 構築時に全件を検証する：1〜128件の配列、各エントリはオブジェクト、`at` は0以上の有限値で重複なく昇順、`temperature` は正の有限値。不正な形式は全て構築時に日本語の理由で拒否する（テストで11形式を固定）。
- 裏経路（返却された config オブジェクトのプロパティ書き換え）は採用しない。h・areaPerVolume・基準温度・スケジュールは構築時に値として取り込んで封印し、ステップ計算では config を再読しない。構築後に config の temperature／temperatureSchedule／h を書き換えても計算結果が完全一致（差0）することをテストで固定した。

### 条件2：状態管理への組み込み — 充足

- スケジュールはカーネルが自身の物理時刻から評価する設計にしたため、実験基盤（初期化時に config を1回だけ渡す。worker.mjs／experiment.mjs）のメッセージ経路の追加は不要だった。
- `snapshot()` は現在の周囲温度 `ambientTemperature` を含む。周囲温度は物理時刻の純関数なので、巻き戻し・A/B比較・履歴と構造的に整合する。証拠：t=50 のスナップショットへ復元すると周囲温度が293.15 Kへ戻り、そこから t=130 まで再開した温度場が無停止ランと完全一致（差0）。t=130 のスナップショット復元では313.15 Kが保たれる。いずれもテストで固定。

### 条件3：安定刻みの扱いの明記 — 充足

- thermal.mjs に明記した：sumG に入るのは `h × areaPerVolume × V` のみで周囲温度の値は安定上限に入らないため、周囲温度だけの時間変化では safeDt は不変であること。将来 h の時間変化まで広げる場合は sumG／safeDt の再計算が必須条件であること（現状は未実装＝設計上の限定）。
- スケジュール有無で safeDt が完全一致することをテストで固定した。

### 条件4：回帰テスト — 充足

- `tests/dynamic-fin-ambient-schedule.test.mjs`（5件、全合格）。検証記録の参照値で固定した：
  - 変化前（t=100 s）：スケジュールラン vs 293.15 K一定ランの温度場の差 = 0（完全一致）。
  - t=130 s：293.15 K一定ランとの最大差が記録値 2.079759043574086 K と 0.005 K 以内で一致。
  - t=600 s：313.15 K一定ランとの最大差 < 1e-4 K（記録 1.84e-5 K）。313.15 K の解析定常（先端断熱 cosh プロファイルのセル平均）との最大差 < 3e-3 K（記録 1.44e-3 K）。
  - t=600 s の相対エネルギー誤差 < 1e-11（記録 6.0e-15）。段差をまたいでも収支は継続する。
  - 切替ちょうどの時刻（t=100）では snapshot の ambientTemperature は変化後の値を示し、温度場は旧周囲で評価された到達ステップの結果として旧ランと一致する（意味論をテストのコメントに明記）。

### 条件5：解禁範囲の切り分け — 充足

- 解禁は汎用画面のみ：lab に「フィン側面の流体温度」入力（従来の293.15 Kリテラルを置換）と「変化時刻／変化後の流体温度」の段差変化1回の入力欄を追加した。複数段が必要な場合は config の temperatureSchedule（最大128件）が受け持つ。
- 学習画面は固定を仕様として FIN_LEARNING.md に明記し、FinJourney が temperatureSchedule を含む条件を拒否することをテストで固定した。

## (b) k(T)／cp(T) 物性テーブルの連成

### 条件1：JS 側の直接回帰テスト — 充足

- `tests/dynamic-fin-variable-properties.test.mjs`（5件、全合格）。検証記録の独立参照を判定材料として埋め込んだ：
  - 定常（k表のみ）：射撃法BVP参照（参照A）のセル平均に対し、最大誤差 nx=24 で < 1.1e-2 K（記録 8.107e-3）、nx=48 で < 2.8e-3 K（記録 2.037e-3）、観測次数 1.8〜2.2（記録 1.99〜2.00）。
  - 過渡（k表＋cp表、nx=48）：エンタルピー形FV＋BDF2/Newton参照（参照B）のプロファイルに対し、t=100 s／600 s とも最大差 < 4e-3 K（記録 2.155e-3／2.005e-3）。dt を safeDt/4 に細分した差は 4e-4〜2e-3 K の範囲（記録 9.96e-4、時間1次収束の署名）。t=600 s の相対エネルギー誤差 < 1e-10（記録 3.3e-12）。

### 条件2：観察・予測式の対応または範囲限定 — 充足（表対応＋範囲限定の併用）

- **重大な罠への対応を実装した**：`finObservation` の基部熱流は、物性表がある場合に公称の定数 k ではなく、**第1セルの現在温度で表を評価した k** を使うよう変更した。これはカーネルの boundaryHeat が基部面コンダクタンスに使う評価（2·k(T₀)·A/Δx）と同一であり、表示が解と一致する。
- 証拠（nx=48、定常）：観察の基部熱流・側面放熱とも参照Aの値 5.2175206390735855 W と 0.01 W 以内で一致し、基部−側面の差は < 2e-3 W。一方、旧来の公称 k 読みでは同じ温度場から 0.1 W 超ずれることをテストで実証した（無条件解禁が危険だった大きさの記録）。
- `steadyFinPrediction`（一定k前提の解析式）は、物性表の条件で公称kを代用せず明示的に拒否する（「解析定常予測は一定物性の専用です」）。
- 学習層は範囲限定を維持：FinJourney は物性表を含む条件を引き続き拒否する（テストで固定）。解禁は汎用画面のみ。

### 条件3：安定刻みの前提確認 — 充足

- 前提を thermal.mjs に明記した：safeDt は表の最小 cp と最大 k で評価する保守的上限であり、分布損失項は T に対して線形（h は温度非依存）で放射のような接線勾配項はない。
- 実測で固定した：粗格子 nx=8・大きな h=500・k表＋cp表の条件で dt=safeDt のまま 60 s まで計算し、5 s ごとの全スナップショットで温度が [293.15, 353.15] K の包絡内、相対エネルギー誤差 < 1e-9。

### 条件4：物性表の範囲と境界評価 — 充足

- 範囲内（表の上限 360 K、基部面の評価温度 353.15 K を含む）：定常まで完走することをテストで固定。
- 範囲外（表の上限 340 K）：基部面の評価 `at(T[0]+q/conductance)` が範囲外となり、初回ステップで「物性表の範囲」エラーで停止する（外挿しない）。cp 表の下限（300 K）を初期温度（293.15 K）が下回る場合は構築時に停止する。いずれもテストで固定。

### 条件5：ブラウザー確認と文書更新 — 未充足（WebKit 未実施）

- 文書更新は実施した：index.html の #manual から「温度依存物性付きのフィンは連成検証待ちのため使用できません」を削除し、解禁範囲・流体温度スケジュール・安定刻みの不変性・学習画面の固定を記述した。FIN_LEARNING.md に学習条件の固定範囲を追記した。
- Chromium では実画面・実 Worker 経由で確認した（`tests/dynamic-fin-coupling-browser.mjs`、開発ソースを配信）：フィンプリセット＋k(T)／cp(T) 表の適用が受理され、モデルラベルに k(T)・cp(T) が表示され、時計が進み、診断の収支表示が出ること。続けて流体温度の段差変化（t=1 s → 40 ℃）を適用し 2.500 s まで計算、エラー表示なし・pageerror なし。
- **WebKit は本環境で起動できない**（MiniBrowser が libgstreamer-1.0.so.0 の欠落で起動失敗）ため未実施。この条件は WebKit 未実施をもって未充足と判定する。計算はエンジン非依存の同一 JS であり、Chromium での実経路確認は済んでいるが、「両エンジン確認済み」とは記録しない。

### 条件6：検証範囲の限定 — 充足（本項の明記をもって）

- 本受入は、検証記録の線形表1組（k(T)：250 K→150、400 K→250 W/(m·K)；cp(T)：250 K→700、400 K→1000 J/(kg·K)）と単一のフィン形状（学習形状：L=0.1 m、断面0.01×0.01 m、h=25 W/(m²·K)、基部353.15 K）による数学的検証の範囲である。全形状・全物性・実機での工学利用承認ではない。教科書 *A Heat Transfer Textbook* 6th ed. の記述と矛盾する変更は含んでいない（フィンの扱いは §4.5 のフィン方程式と先端断熱の枠組みの内側にある）。
