# 自然対流キャビティの高 Ra 化 JS 移植（Ra≤1e6）

記録日：2026-11-07。ブランチ `feiris/highra-cavity-js`（基点＝統合先端 34b84ad）。
担当：Muse 本線の残開発。push・PR はしない（ローカルコミットのみ）。

## 1. 目的と範囲

- 目的：開発用ソルバー `dynamic/dev/cavity.mjs`（MAC 有限体積・投影法）の自然対流の受理上限を Ra≤1000 から Ra≤1e6 へ引き上げ、既存の multigrid 前処理（`dynamic/dev/poisson-multigrid.mjs`）の経路で de Vahl Davis ベンチマーク（Pr=0.71）に対して検証する。
- 根拠：Codex サポート依頼1（ブランチ `codex/support-natconv-ra-range` @83f9f04、記録 `docs/dynamic/support-natconv/README.md`）が Python プロトタイプ（MAC＋DCT 投影）で Ra=1e4／1e5／1e6 の到達可能性を実証した。ただし DCT は矩形・定数係数の分離可能性に依存し本線の方式には使えない（Codex 自身の線引き）。本線では既存 multigrid 投影の経路で移植する（フェイリスの統合判断）。
- 対象外（明示）：
  - `dynamic/dev/thermal-wall-cavity.mjs`（有限容量壁との連成モデル）は変更しない。その Ra≤1000 制限は壁連成モデルの状態ごとの実効 Ra ガードであり、固定壁温ペアのベンチマーク構成ではないため、高 Ra 化は別課題とする。
  - 公開側・開発画面（`cavity-ui-config.mjs`）の受理範囲は変更しない。画面は従来どおり Ra≤1000・検証済みの Pr／アスペクト比／格子の範囲だけを受け付ける（画面側の範囲は画面自身のガードで維持する。第3節参照）。
  - 乱流・3次元・非定常流（Ra=1e6・Pr=0.71 の2次元問題は定常）には踏み込まない。

## 2. 方式

- 計算核は既存の `createCavity` をそのまま使う：スタガード MAC 有限体積、運動量は保存形2次（conservative2）、温度は中心差分（central、セル Pe≤2 のガード付き）、圧力 Poisson は PCG＋Neumann multigrid 前処理（Galerkin V-cycle）。時間積分は陽的（ソルバーの `safeDt`＝拡散／移流制限の小さい方）。
- 変更点は上限と内部の最大値走査の実装だけに限定する（第3節）。離散化・更新則・Nu 定義は一切変更しない。ソルバーの `nusselt` は Nu_0（高温壁の平均伝導熱流束基準）であり、de Vahl Davis の Nu_0 に対応する（`docs/dynamic/DE_VAHL_DEFINITIONS_20261106.md`）。
- 高 Ra 化の前提として実測した環境事実：`Math.max(...array)` の spread は 65,536 要素（256²）まで動作し 131,072 要素で RangeError。また spread＋map の最大値走査は 65,536 要素で約32 ms／回、ループ走査は約1 ms／回。従来の `maxAbs`（spread 形）はステップごとに複数回呼ばれるため、高格子では実行時間の支配項になる。有限値に対する最大値としては走査順に依らず厳密に同一なので、ループ形へ置換する（数値変更なし）。

## 3. コード変更（予定を事前記載し、実施後に実績を追記する）

1. `dynamic/dev/cavity.mjs`：格子上限 96→256、Ra 上限 1000→1e6（1+1e-12 の相対許容は従来どおり）。`maxAbs` をループ形へ（数値同一）。Boussinesq 逸脱量の走査も中間配列を作らない形へ（数値同一）。追加の性能変更（いずれも演算の順序・値が同一であることをビット一致で確認する）：内積 `dot` と projectFaces 内の `zeroMean` を reduce から同一順序のループへ、毎ステップ走る有限性述語を spread からループ走査へ置換。
2. `dynamic/dev/poisson-multigrid.mjs`：格子上限 128→256。追加の性能変更：`zeroMean` を同一順序のループへ置換し、サイクル内の制限／補間ループで使う prolongation のペア配列を、同じペア順序のまま平坦な型付き配列へ複写する（蓄積順序が同一のため結果はビット一致。旧版との apply 出力の完全一致を 32／128／192 格子で確認済み）。Galerkin 粗格子演算子には打切り誤差の相殺残差（対角比 ~1e-16）が非零として残り疎性が下がるが、演算子自体には手を入れない（前処理の数値を変えないため）。
3. `dynamic/dev/cavity-ui-config.mjs`：画面の受理範囲（Ra≤1000、幅方向格子 4〜96）を画面自身のガードとして明示し直す。従来はカーネルの拒否に依存していたため、カーネル上限の引き上げに伴い画面側で同じ文言の拒否を維持する。画面が提供する条件の集合は変更しない。
4. 新規テスト `tests/dynamic-cavity-highra.test.mjs`（短時間で終わる検証のみ）と、新規ベンチマークランナー `scripts/dynamic-cavity-highra-benchmarks.mjs`（定常判定付き長時間実行用。スイートには含めない）。

## 4. 受理基準（事前登録：実行前に固定し、結果を見てから緩めない）

### 4.1 ベンチマーク設定（全ケース共通）

正方形キャビティ L=H=1、rho=cp=1、alpha=1、nu=0.71（Pr=0.71）、左壁 300.5 K・右壁 299.5 K（ΔT=1 K）、初期・基準温度 300 K、beta=0.001、gravityBeta=0.71·Ra、scalarScheme='central'、momentumScheme='conservative2'、pressurePreconditioner='multigrid'、pressureTolerance=1e-11、maxPressureIterations=4000。Ra=1000 の既存ベンチマーク（`scripts/dynamic-cavity-benchmarks.mjs`）と同一の無次元化であり、Ra だけを変える。

### 4.2 定常判定

無次元時刻 τ（=alpha·t/H²=t）で 0.01 ごとに Nu_0 を記録する。τ≥0.4 かつ直近 Δτ=0.1 の窓での Nu_0 の相対変化が 2e-5 未満になった時点で定常と判定する。上限は τ=3.0 とし、到達しなければ「未収束」として最終ドリフト率とともに記録する（合格扱いにしない）。

#### 4.2.1 性能実測に基づく改訂（2026-11-07、結果を見る前に追記）

陽的時間積分のステップ単価を実測したところ、multigrid 前処理付きでも 128² で約66 ms/step、192² で約190 ms/step であり、コールドスタートのままでは 192² の τ=1 に約55万ステップ（約29時間相当）を要する。そこで格子シーケンシングを導入する：粗い格子で定常化した場を双線形補間で細格子へ移し、`projectFaces` で離散発散を除去してから `restore` で投入する（カーネルの API・離散化は変更しない。投入時のエネルギー基線は、復元状態の netInput を「ウォーム場の内部エネルギー − 一様初期場の内部エネルギー」に設定することで、区間内の保存誤差が snapshot の energyError として正しく読めるようにする）。

- コールド区間（各 Ra の最粗格子）：定常判定は本節の原基準（τ≥0.4＋ドリフト条件、上限 τ=3.0）。
- ウォーム区間（補間投入した区間）：物理時間は粗格子側で既に蓄積されているため、定常判定を「区間 τ≥0.15、かつ直近 Δτ=0.1 窓のドリフト <2e-5、かつ区間最終 Nu_0 が前段（粗格子）の定常 Nu_0 から 0.5% 以内」に改める。区間上限は τ=0.8 とし、到達しなければ未収束として記録する。
- Ra=1e6 の格子収束の集合は 128／160／192 に改める（256² は約390 ms/step と見積もられ、区間だけで十数時間規模になるため本キャンペーンでは未実施とする。カーネルの 256 対応自体は構成テストで担保する）。Ra=1e4 は 48／64／96、Ra=1e5 は 96／128／192（シーケンシングの前段として 64 を追加してよいが、報告する収束集合はこの3格子とする）。

### 4.3 合格条件

- AC1（基準値）：対応格子（Ra=1e4 は 64²、1e5 は 128²、1e6 は 192²）で、de Vahl Davis 値に対する相対差が 1.0% 以内。基準値は headline の Nu（1e4: 2.243、1e5: 4.519、1e6: 8.800）を主とし、1e6 では Nu_0=8.817 に対する差も併記する。
- AC2（Python 参照）：同格子でサポート依頼1の Python 参照値（1e4: 2.250632、1e5: 4.531632、1e6: 8.852661）に対する相対差が 1.0% 以内。
- AC3（格子収束）：各 Ra で3格子（1e4: 48／64／96、1e5: 96／128／192、1e6: 128／160／192。§4.2.1 の改訂による）について、格子を細かくするほど Nu_0 の増分の絶対値が縮小する（単調収束）こと。Richardson 外挿値と見かけの次数を記録する。
- AC4（保存性）：各実行の最終状態で relativeEnergyError ≤1e-6、かつ実行が発散・連続性ガードで停止しないこと。
- AC5（回帰）：全 Node スイートで失敗0。加えて既存ベンチマーク（Ra=1000、jacobi 前処理、t=1）の 32² の Nu_0 が従来記録 1.11994276 に対して ±0.002 以内（カーネル変更が低 Ra の数値を動かしていないことの直接確認）。
- 残件確認（合否対象外、結果を記録する）：Ra=1e6・128² のコールドスタート（サポート依頼1で Python 側が失敗した条件）の成否。壁面局所 Nu の最大値の格子依存（スナップショットの温度場から独立に集計する）。ブラウザー（Chromium）での1ステップ実行時間の実測。

## 5. 実測結果

### 5.1 Ra=1e4（完了）

| 格子 | 区間 | Nu_0 | de Vahl Davis 2.243 との差 | Python 参照との差 | 定常 |
|---|---|---|---|---|---|
| 48² | cold | 2.25514111 | +0.541% | — | τ=0.4 で定常（ドリフト 2.7e-6） |
| 64² | warm | 2.25063260 | +0.340% | 2.250632 に対し +0.00003% | 定常（ドリフト 2.0e-5 未満） |
| 96² | warm | 2.24846599 | +0.244% | — | 定常（区間 τ=0.18、ドリフト 1.1e-5） |

64² の Nu_0 は Python プロトタイプ（DCT 投影）の同格子の値と小数6桁まで一致した。異なる投影方式・異なる離散化実装の間での強い相互検証である。エネルギー保存の相対誤差は全区間 1e-13 以下。局所最大壁 Nu（温度場から独立に再計算）：48² で 3.682、64² で 3.611、96² で 3.578（細格子ほど小さく、単調）。

格子収束（AC3）：増分は 48→64 で −0.00451、64→96 で −0.00217 と縮小し単調収束。三点 Richardson 外挿（Nu(h)=Nu∞+C·h^p の厳密解）では見かけの次数 p≈3.20、外挿値 Nu∞=2.24765（de Vahl Davis 比 +0.207%）。AC1（64² で 1% 以内）・AC2 ともに合格。

### 5.3 Ra=1e6（完了）とコールドスタート診断（サポート依頼1の残件）

| 格子 | 区間 | Nu_0 | de Vahl Davis 8.800 との差 | Nu_0 定義値 8.817 との差 | Python 参照との差 | 定常 |
|---|---|---|---|---|---|---|
| 192² | warm（Ra=1e5 の同格子定常場から Ra 継続） | 8.85266116 | +0.598% | +0.404% | 8.852661 に対し +0.000002% | 定常（区間 τ=0.3、ドリフト 4.3e-8） |
| 160² | warm（192² から） | 8.86471571 | +0.735% | +0.541% | （同格子の参照なし） | 定常 |
| 128² | warm（160² から） | 8.88686128 | +0.987% | +0.792% | （同格子の参照なし） | 定常 |

特記：192² の Nu_0 は Python プロトタイプ（DCT 投影）の同格子の値 8.852661 と小数6桁まで一致し、de Vahl Davis 比も Python 側の記録 +0.598% と一致した。Ra=1e4 の 64²、Ra=1e5 の 128² に続く3例目の強い相互検証であり、3つの Ra すべてで「JS multigrid 経路＝Python DCT 経路」が同格子で 1e-6 相対まで一致した。

格子収束（AC3）：128／160／192 の増分は（細→粗の向きで）−0.01205、−0.02215 と細格子ほど縮小し単調収束。三点 Richardson 外挿では見かけの次数 p≈1.99（公称2次と一致）、外挿値 Nu∞=8.82510（de Vahl Davis 比 +0.285%、Nu_0 定義値 8.817 比 +0.092%）。AC1（192² で 1% 以内、実測 +0.598%）・AC2（同 +0.000002%）ともに合格。エネルギー保存の相対誤差は全区間 6e-13 以下。ステップ単価（Node、192²、定常近傍を含む区間平均）126 ms/step。

到達経路の記録（重要）：一様場からのコールドスタートは 64²・128² ともに中心差分のセル Pe ガードで停止した。128² で失敗直前まで計測した過渡は次のとおり：max|v| は τ=0.0056 で 131、0.0081 で 188、0.0106 で 221、0.0132 で 253.5 とほぼ線形に増え続け、τ≈0.0135 で Pe 閾値（|u|>256）に達した。高温壁の浮力シートが戻り流れに制動される前にほぼ自由加速する物理的な過渡オーバーシュートであり（定常の max|v| は約220）、ソルバーの不具合ではない。ガードは設計どおりに働いている。これが Python プロトタイプの「Ra=1e6、128² コールドスタート失敗」と同一の現象である。Ra=1e5 の定常場から 128² で Ra 継続する経路も同じガードに触れた（調整過渡で再び閾値を超える）ため、最終的には Pe 閾値に余裕のある 192²（|u|>384 で発火）で Ra 継続し、収束場から粗い格子へ下ろす順序で全格子を得た。一次風上への切替は離散化そのものの変更になるため行わない。

局所最大壁 Nu（温度場から独立再計算）は 128² で 18.024、160² で 17.845、192² で 17.751 と単調減少。Ra=1e5 の確定値でも単調減少であり、本キャンペーン初回に観測された非単調性は実行経路への敏感さの現れで、確定した系列では再現しなかった（§5.2 の注記参照）。

### 5.4 Ra=1000 アンカー（AC5 の一部、先行実施）

既存ベンチマークスクリプト `scripts/dynamic-cavity-benchmarks.mjs`（jacobi 経路、t=1）をそのまま実行：32² の Nu=1.1199427558 で、記録値 1.11994276 との差は 4.2e-9。de Vahl Davis 1.117 に対する acceptance も passed。multigrid 経路のアンカーは `tests/dynamic-cavity-highra.test.mjs` で別途担保（±0.002 以内）。

### 5.5 実行時間

陽的時間積分のため、無次元時刻あたりのステップ数は格子の2乗に比例する（192² で τ=1 に約37万ステップ）。ステップ単価の実測：

| 環境 | 128² | 192² |
|---|---|---|
| Node v24（本 VM、定常近傍） | 約66 ms/step | 約126〜172 ms/step（区間・負荷で変動） |
| Chromium 141 ヘッドレス（本 VM、無競合時） | 83.6 ms/step | 188.6 ms/step |

Chromium 計測はキャンペーン実行と競合した初回（128² で 188 ms/step、192² で 444 ms/step）より無競合時の値を採用した。いずれにせよ 192² で定常に届くまでの対話的実行は現実的でなく（τ=0.3 の区間だけでもブラウザーで約16時間相当）、高 Ra の成果は開発側のベンチマーク検証に留めるのが妥当である。公開画面の受入範囲（Ra≤1000、格子は画面の検証済み範囲）は従来どおり変更していない。ブラウザー側の実働確認として、開発画面のブラウザーテスト `tests/dynamic-cavity-browser.mjs` は Chromium で全項目合格（passed: true。offlineVerified のみ false で、これは当該テストの従来どおりの申告範囲）。

### 5.6 受理基準の判定

- AC1（対 de Vahl Davis、同格子で 1.0% 以内）：合格。1e4@64² +0.340%、1e5@128² +0.280%、1e6@192² +0.598%（Nu_0 定義値 8.817 に対しては +0.404%）。
- AC2（対 Python 参照、同格子で 1.0% 以内）：合格。実測は +0.00003%（1e4）、+0.00002%（1e5）、+0.000002%（1e6）と、3点すべてで小数6桁まで一致した。
- AC3（格子収束）：合格。3つの Ra すべてで増分が縮小する単調収束。Richardson 外挿値と de Vahl Davis の差は 1e4 で +0.207%（p≈3.20）、1e5 で −0.003%（p≈1.59）、1e6 で +0.285%（p≈1.99）。
- AC4（エネルギー保存）：合格。全区間の最終 relativeEnergyError は 1e-12 以下（最大で 192²@1e5 の 5.9e-13）で、発散ガードによる停止はなかった。
- AC5（回帰）：合格。全 Node スイート 1,675件＝1,670合格／0失敗／5スキップ（基点 1,671件＋新規4件）。Ra=1000 アンカーは既存スクリプト実測 1.1199427558（記録値との差 4.2e-9）と新規テストの multigrid 経路の両方で確認。公開ビルド成功、dist 棚卸し不変（節76件、dynamic 47エントリ、用語集504件、開発混入0）。

## 6. 残件・未実施事項

- 256² 格子でのベンチマークは未実施（カーネル対応は構成テストで担保）。理由は §4.2.1 に記録した実測コストであり、受理判定には 128／160／192 の3格子で足りると判断した。
- Ra=1e6 のコールドスタートは中心差分のままでは成立しない（§5.3）。成立させるには過渡の扱い（初期場の工夫、Ra ランプ、風上化など離散化変更）が必要で、本タスクの範囲外として残す。到達自体は格子シーケンシング＋Ra 継続で達成済み。
- `thermal-wall-cavity`（有限熱容量壁の conjugate モデル）の高 Ra 化は対象外のまま（§1）。その Ra≤1000 は状態ごとの実効 Ra ガードであり、固定壁ベンチマークとは別モデルである。
- 高 Ra 結果の公開側への反映（受入範囲の変更）は行っていない。反映する場合は §5.5 の実行時間が示すとおり対話実行の設計（事前計算済み結果の表示、Worker 化と進捗設計など）が別途必要になる。
- WebKit での実行確認は未実施（本 VM では WebKit ランタイムが起動できない。Chromium のみ実測）。
- Galerkin 粗格子演算子の疎性低下（相殺残差 ~1e-16 を保持）は性能上の既知事項として残す。前処理の数値を変える変更は本タスクでは行わなかった。
