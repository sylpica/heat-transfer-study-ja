# 教材・問題から動的実験へ

共有インターフェースは `dynamic-navigation.mjs` に分離。翻訳・問題・用語データは変更せず、app.jsには節の直接移動、読書の関連実験リンク、回答後の限定的な問題リンクだけを追加する。Museとの統合時はこの3箇所を保護し、本文の翻訳作業と混ぜない。

## 教材と節の移動

`#reader/5.3` のようなフラグメントで実在する節を開ける。初回読み込みと、同じ読書画面内の別の節へのhash変更をそれぞれ処理する。任意のHTML/コードや未知の節をフラグメントから実行しない。既存の読書位置・メモ・読了の処理を使用する。

読書の§2.1/2.2/4.5/5.3/5.4/5.5/5.8/7.2/10.1/10.3には、対応する代表実験への別タブリンクを追加。教材の説明/例題をそのまま数値化したと見せず、アプリの代表条件であることを案内する。§7.2のリンク先は完全発達・周期温度の限定流路であり、入口/出口/壁面熱伝達を計算する一般管内CFDとは呼ばない。自然対流の代わりに無関係な近似モデルを案内しない。

熱伝導画面は `?preset=heating&section=5.3` 等を受け、対応する既知の実験/節の組だけを許可する。関連教材へのリンクは実際の節へ戻る。自由な数値式や物性をURLから実行しない。未対応・重複・矛盾した引数は標準実験に戻し、受け取れなかった旨を表示する。後続のRADIAL_UI.mdでは、円筒/球・放射・流路にも実在節の文脈を照合した戻りリンクを追加。全節の起動導線は後続課題。

## 問題の条件引き継ぎ

初回対象は `supp-deep-fin-base-heat-v1`（v1）のみ。問題本文/選択肢/正答/改訂/段階解法から作る既存questionFingerprintの検査値と、ID・revisionが一致した場合に限り、**回答後**の解説へリンクを出す。設問が改訂されたら無条件に同じ条件を流用せず、確認してから再登録する。検査値は高速な変更検出であり、認証用の暗号署名ではない。

`?case=fin-base-v1` は L=0.10 m、Ac=10⁻⁴ m²、P=0.040 m、k=200 W/(m K)、h=25 W/(m² K)、ΔT=60 K、断熱先端を設定。矩形断面0.01×0.01 mでP/Acを一致させる。元の問いは定常であることを表示し、過渡観察用に周囲20℃・基部80℃・初期20℃と、設問にないρ=2700 kg/m³・cp=896 J/(kg K)を仮定したことを明記する。実物の材質/熱容量を特定したとは扱わない。入力を変更した後は元条件との一致を保証しない。時間軸から元の設問の答えを自動評価しない。

48セルの1D解を別のcosh解析温度分布/基部熱量と照合。600 sで最大温度差は約0.00162 K（基準0.003 K）、基部の熱量差は約0.000166 W（基準0.003 W）、解析値約5.166343 W。初回400 sでは温度差約0.00458 Kで不合格だったため、許容幅を変えず十分な緩和時間600 sで再検査した。最も遅いモードの緩和時間はおよそ41 sで、400 sでも有限な過渡の残りがある。UIは自動で定常になると表示せず、通常どおり過渡計算を開始する。密度/比熱の補足が定常解を変えないことと、過渡時間はそれらに依存することを区別する。

別タブで元の問題画面を維持し、動的画面から回答・自信度・履歴・復習データへ書き込まない。元の問題データも変更しない。全問の条件自動抽出は実装していない。

## Pagesと未訪問URLのオフライン

新しいクエリ付きの実験URLが未取得のとき、従来のService Workerはrootのindex.htmlへフォールバックし、実験ではなくアプリ本体が表示される。対応する3つの動的HTMLとdynamic/だけをパスの許可リストで判定し、同じ正規HTMLのキャッシュを使ってクエリはJavaScript側で検証する。非ナビゲーション要求や任意の別パスへ一般化しない。PDFの専用キャッシュ/明示保存/Range処理を変更しない。

新しい配信物ブラウザー試験は `/heat-transfer-study-ja/` のサブパスで実行。教材→実験、初回/同画面の節指定、回答前のリンク非表示、回答後のフィン全入力、履歴の不変、未知ケースの標準への復帰、**一度も取得していないクエリURLへのオフライン移動と再訪→正しい節への復帰**を検査する。Chromiumはブラウザーオフライン、WebKit CIは配信サーバーを閉じたSWフォールバックを使用する。WebKit/実機は各保存SHAの実行結果が出るまで確認済みとしない。

初回E2Eでは折りたたまれた説明書内の戻りリンクをクリックしようとして失敗。受け取った条件の説明に可視の戻りリンクを設け、実際の操作で再検査した。Nodeの既存VMハーネスにも、新しい実モジュールを渡す必要があり修正した。スタブで導線を無効化したり、試験を削除したりしていない。
