# 専門解析モードの解法設定の露出（Phase 5 残件 P5-3）（2026-11-07）

棚卸し台帳（`PHASE57_INVENTORY_20261107.md`）の P5-3「公開ラボの専門モードで
収束許容値を利用者が変更する経路はない（格子・時間刻みは変更可）。解法設定の
露出は設計判断を要する」への対応記録。設計判断として、露出してよい設定だけを
専門解析側の画面から変更できるようにした。

- 作業ブランチ：`feiris/solver-settings`（基点＝統合先端 `34b84ad`）
- 判断の方針（ユーザー）：より高度で多機能で使いやすく。ただし検証済みの
  受理範囲を壊す露出はしない。

## 1. 現状調査：各ソルバーの収束許容値・最大反復数

### 公開ラボ（`dynamic/` 直下、Worker 経由の4モデル）

| ソルバー | 反復・許容値の実態 |
|---|---|
| `thermal.mjs`（2D伝導／フィン） | 陽的 FVM。放射境界の面温度は固定52回の二分法（許容値という概念がない）。対流＋放射面は `surfaceExchange` に委譲 |
| `surface-exchange.mjs` | 保護付き Newton、最大96回、収束判定は相対残差 ≦ 64·EPSILON（丸め誤差水準）。受理記録で Kirchhoff 厳密解との一致（表面温度 2.7e-10 K 以内）まで検証済みの核 |
| `radial.mjs` | 陽的。放射外面は固定60回の二分法 |
| `developed-channel.mjs` | 陽的。反復なし |
| `radiation-network.mjs` | 直接法（Gauss 消去）＋残差ゲート相対 1e-10。これは収束許容値ではなく、悪条件な系を受け付けないための妥当性ゲート |
| `lumped-radial.mjs` | 反復なし |

### 開発側の専門解析（`dynamic/dev/`）

| ソルバー | 反復・許容値の実態 |
|---|---|
| `cavity.mjs` の `projectFaces` | 圧力投影の PCG（multigrid／Jacobi 前処理）。`pressureTolerance`（相対、核の既定 1e-10）と `maxPressureIterations`（既定 2000）を条件で指定可能。投影後は連続の式のゲート（相対 1e-8）で刻みを検証し、超えれば停止する |
| `poisson-multigrid.mjs` | 固定1回の V サイクル前処理（平滑化2スイープ固定）。収束判定を持たず、外側 PCG が判定する。設定として露出できる量が存在しない |
| `thermal-wall-cavity.mjs` | `projectFaces` を流用。モデル層で `pressureTolerance` 既定 1e-12・上限 1e-10、`maxPressureIterations` 既定 2000・範囲 1〜5000 を検証済み |
| `natural-convection-wall.mjs` | 台形選点＋Newton（残差 <1e-12、最大40回）。Ostrach 表と照合済みの相似解ソルバーで、反復設定は検証済み解法の一部 |
| `triangle-*-flux-recovery.mjs`（3件） | 温度場の後処理回復の PCG。許容値 1e-11・上限 8×要素数に固定され、検証済み回復手続きの一部 |
| `box-radiation-3d.mjs` | `NETWORK_TOLERANCE` は形態係数の受理ゲート（妥当性判定） |
| `cess-profile.mjs` | Gauss 点の Newton（4·EPSILON で停止、最大32回）。丸め誤差水準 |
| `blasius-boundary-flow.mjs` | f″(0) の二分法60回固定 |
| その他の dev モデル（Graetz／加熱管／RANS／共役流路／ヒートシンク／3D直方体ほか） | 陽解法・直接法・級数打ち切りで、利用者向けの反復収束許容値を持たない（打ち切りはモデル定義の一部） |

画面側の実態：キャビティ系の UI ビルダー2件（`cavity-ui-config.mjs`、
`lid-cavity-ui-config.mjs`）が `pressureTolerance: 1e-11`、
`maxPressureIterations: 4000` を固定値で埋め込んでおり、利用者が画面から
変える経路はなかった。熱壁の UI ビルダー（`thermal-wall-ui-config.mjs`）は
設定自体を渡していない（モデルの既定 1e-12／2000 が効いている）。

## 2. 切り分け：露出するもの／しないものと根拠

### 露出する（本ラインで実装）

- **キャビティ系2画面（自然対流 `cavity.html`、移動壁 `lid-cavity.html`）の
  圧力反復の収束許容値（相対）と上限回数。**
  本物の反復ソルバーの収束設定であり、条件→Worker→計算核まで既に配線され、
  スナップショットの署名にも含まれている。画面の固定値を入力に置き換える
  だけで、計算核には手を入れない。

安全範囲（画面側の検証）：

- 許容値：**1e-13〜1e-10**。上限 1e-10 は、ファミリー内で最も厳しいモデル層の
  上限（熱壁モデルが >1e-10 を拒否）であり、キャビティ計算核自身の既定値でも
  ある。下限 1e-13 は、PCG の停止閾値 `max(1e-12, 許容値×右辺ノルム)` に
  絶対下限があるため、これ未満は実効を持ちにくく未収束エラーを招くだけで
  あることによる。
- 上限回数：**1〜5000 の整数**（熱壁モデルの範囲と一致。画面既定 4000 を含む）。
- 計算核（`cavity.mjs`）自体には範囲制限を足していない。核は連続条件ゲートで
  刻みを拒否する設計であり、核レベルの既存テストが意図的に緩い許容値（2）を
  使ってゲートの発動を検証している。範囲を絞るのは画面層の役割とした。

### 露出しない

- **公開ラボの各ソルバー**：非線形の代数求解（表面収支 Newton・放射面の
  二分法）は丸め誤差水準まで駆動する設計で、検証済みの受理値そのものが
  その水準で得られている。緩める余地は「精度を落とす」ことでしかなく、
  厳しくする余地は倍精度の範囲にない。放射ネットワークの残差 1e-10 は
  妥当性ゲートであり、緩めると検証で棄却された系を受け付けてしまう。
  → 公開側に露出できる反復収束許容値は存在しない、が結論。
- **熱壁キャビティ画面**：モデル層には設定と検証があるが、画面ビルダー
  `thermal-wall-ui-config.mjs` は凍結参照 `THERMAL_WALL_AIR_REFERENCE_20261107_v1.json`
  の SHA-256 固定と出力の deepEqual 照合の対象であり、変更すると現行の
  検証テストが壊れ凍結記録と矛盾する。露出は参照の再発行とセットでなければ
  行えないため、本ラインでは対象外とし、ここに根拠を記録する。
- **multigrid の内部**：固定前処理であり収束設定が存在しない（上表）。
- **相似解 Newton・熱流束回復 PCG・Gauss 点 Newton・二分法**：いずれも
  検証済み手続きの一部として固定されており、変えると照合済みの参照値の
  前提が崩れる。
- **各所の妥当性ゲート**（放射ネットワーク残差、形態係数受理、最大原理の
  丸め予算など）：収束許容値ではなく棄却条件であり、露出対象ではない。

## 3. 実装範囲

- `dynamic/dev/cavity-ui-config.mjs`／`lid-cavity-ui-config.mjs`：
  `pressureTolerance`／`maxPressureIterations` のキーを受け付け、既定値は
  従来の固定値（1e-11／4000）のまま、§2 の安全範囲を日本語の理由つきで
  検証して条件へ載せる。検証は各ビルダー内に自己完結させた（新規モジュールを
  足すと既存ブラウザテストの配信許可リストを壊すため、このコードベースの
  ビルダーの慣行どおり）。
- `dynamic/dev/cavity.html`／`lid-cavity.html`：条件フォームに2入力を追加。
  `min`／`max` 属性は付けていない。付けると送信前にブラウザのネイティブ
  検証が先行し、アプリ側の日本語の理由が表示されないためで、範囲の検証は
  ビルダーが行い、拒否理由を画面のエラー欄に日本語で表示する。診断の
  details に範囲・既定・変更時の振る舞いの説明を置いた（画面下部）。
- `dynamic/dev/cavity-ui.mjs`／`lid-cavity-ui.mjs`：`config()` で2入力を
  読み、変更時は他条件と同様に無効化して再初期化を促す。診断表示に
  「許容値」「上限反復」を追加し、適用中の設定が画面で確認できる。
- 新規テスト `tests/dynamic-solver-settings.test.mjs`（7件）。

## 4. 保存・復元

- 設定は条件 config の一部として流れ、A/B 比較の固定（config 全体の複製）に
  そのまま含まれる。
- キャビティ計算核のスナップショット署名は `pressureTolerance` と
  `maxPressureIterations` を含むため、設定の異なるモデルへの復元は署名
  不一致で拒否される（新規テストで固定）。履歴の巻き戻しは同一条件の中で
  のみ有効という既存仕様と整合する。

## 5. 検証実測

- **既定値の不変**：設定を省いたビルダー出力は、従来値を明示した出力と
  deepEqual で一致。移動壁モデルでは、省いた場合と 1e-11／4000 を明示した
  場合で3ステップ後のスナップショットがビット単位で一致（新規テスト）。
- **設定変更時の方向性**（移動壁キャビティ Re=100、16×16、10ステップ、
  t=0.0625 s、画面ビルダー経由）：
  - 許容値 1e-10（緩い）：最終残差 4.59e-9、累積反復 71 回、投影後の発散 5.24e-12
  - 許容値 1e-11（既定）：最終残差 2.93e-10、累積反復 81 回、発散 2.84e-13
  - 許容値 1e-13（厳しい）：最終残差 9.82e-13、累積反復 99 回、発散 1.28e-15
  - 緩い設定と厳しい設定の速度場の差は最大 1.61e-13、圧力差は最大 1.14e-13
    （同じ投影場の近似であることを確認）。各実行とも残差は自らの停止 bound
    `max(1e-12, 許容値×右辺ノルム)` 以下。
- **範囲外の拒否**：許容値 1e-9／1e-14／0／負値／NaN／文字列、上限回数
  0／5001／小数／NaN／文字列は、両ビルダーとも日本語の理由（/圧力反復/）で
  拒否（新規テスト）。実画面でも 1e-9 の入力がエラー欄に理由つきで拒否
  されることを確認（下記レンダリング確認）。
- **全 Node スイート**：1,678件＝1,673合格／0失敗／5スキップ
  （基点 1,671件＝1,666合格／0失敗／5スキップから、新規7件のみ増加し
  失敗0を維持）。関連既存テスト（cavity-ui-config／lid preset／lid view／
  thermal-wall-air／cavity-state／multigrid／manufactured／mac-momentum／

## 6. 残件

- 熱壁キャビティ画面への設定露出は、凍結参照
  `THERMAL_WALL_AIR_REFERENCE_20261107_v1.json` の再発行とセットでのみ可能
  （§2 の根拠）。本ラインでは行わない。
- P5-3 の設計判断は本記録を正本とする：露出はキャビティ系の専門解析画面で
  行い、公開ラボでは検証済み受理範囲を守るため露出しない。
- 自然対流ブラウザテストの 64×64 タイムアウトは負荷環境の既知のフレーク
  （基点でも再現）。低負荷時の再実行は監査フェーズの確認事項とする。
