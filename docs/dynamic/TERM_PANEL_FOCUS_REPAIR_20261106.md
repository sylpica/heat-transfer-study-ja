# 動的用語パネル：遅れたcloseイベントのフォーカス修正

2026-11-06（Asia/Tokyo）。rootが単独・逐次実行。Phase5の追加ではなく、既存の動的学習画面で確認した回帰不具合の修正。

## 原因と修正

5faaa22のCI42118295655、Chromium job127563668533で `tests/dynamic-fin-learning-browser.mjs` が失敗。「フィン効率」を閉じ、次の「フィン有効度」にフォーカスしてEnterを押す操作で、題名が前の「フィン効率」のままだった。WebKit/数値/高次MMS成功とは別の失敗で、全CI成功ではない。

`dynamic/term-panel.mjs` はdialogのcloseイベントごとに無条件で起点へfocusしていた。ブラウザー標準のフォーカス復帰と次の操作が先に済み、遅れたcloseタスクが届くと、すでに移したフォーカスを前の起点へ戻してしまう。

新しい隔離ブラウザー試験で、実際のdialog.close→次用語へfocus→遅れたcloseイベントを再現した。修正前は期待secondに対してfirstへ戻り、同じアサーションが実際に失敗。タイムアウトや期待値を変えず、実装を修正した。

close処理は、ダイアログが再度開いておらず、フォーカスが閉じたダイアログ/body等に残る場合だけ起点へ戻す。すでに別の要素へ意図して移った場合は維持する。ネイティブ復帰が働かない場合のフォールバック、関連語、Enter/Space/Escape、モーダル再開後のフォーカスは保持する。数式/モデル/学習保存形式は変更しない。
