# 保存的回復流束の任意表示

2026-11-06。基点a5ed7d7の限定検証済みRT0後処理を、凸P1の開発GUIへ接続した。公開allowlistへは含めない。

## 表示と状態

チェックボックスでRT0の要素重心流束を矢印表示する。生の−k∇Tとは別の保存的後処理で、温度誤差を解消しない旨を明示。A/Bで同じ線形長さ尺度を用い、24 CSS pxに対応するW/m²を表示する。実ベクトルの向きと大きさを使い、画面yだけを反転する。最大40点を間引いて重心へ配置し、矢印は流跡線や要素界面の全流束を表すものではない。

元の勾配流束、回復流束の測定値、回復境界熱、離散反力との差、要素収支最大残差と予算、CG反復を別々に表示する。内部辺上では測定した片側要素を区別し、法線連続と接線不連続を混同しない。領域外/所属しない回復要素の値は作らない。

128EPS×表示最大重心流束以下は矢印表示だけ省略する。物理データ・数値診断は変更しない。表示対象の重心流束が0なら矢印を描かず、0を24pxの流束と説明しない。条件ごとの回復失敗は利用不可として案内し、0の流束を偽装しない。

回復は受理したメッシュ/物性/発熱と実状態だけから計算する。メッシュごとの解析器と状態ごとの結果をWeakMapへキャッシュし、プローブ移動・再描画だけで毎回CGを解かない。保持状態のコピーを改変しない。回復の失敗は温度計算・再生・復元を止めず、回復矢印と測定だけを利用不可にする。

## 検証

新規の表示2試験は、手計算3-4-5ベクトル、A/B倍の大きさで倍の長さ、xy符号、ゼロ場、間引き、極小値の表示限定省略、不正尺度/非有限値の拒否を確認した。

Chromium/WebKitの実GUI/Workerで、矢印データを実RT0要素重心値へ照合、A/B共通倍率、加熱冷却反転、等温時の矢印なし、表示切替による温度/時計不変更を確認。既存の全P1 GUIシナリオ（CPU/連続解、巻き戻し、取消再開、無効刻み、形状予算、領域外、キーボード、明暗/モバイル/DPR2/保存）も成功。さらに回復モジュールのエラーを意図的に注入し、利用不可表示と矢印なしのまま実Workerがt=1へ進むことを両エンジンで確認した。これはモデルを成功へ差し替えた試験ではなく、後処理失敗から物理更新を分離する回復試験。

凸輪郭編集の両ブラウザー回帰も成功。スクリーンショットは実装担当が目視し、実際の外向き流束・白黒輪郭の矢印・測定点・軸/単位が読めることを確認した。全Node1363件中1358成功・5スキップ・失敗0、test-concurrency=1。公開ビルド成功、devは除外、公開Worker/cache不変更。ハッシュと実測はTRIANGLE_FLUX_UI_CHECKPOINT_20261106.json。
